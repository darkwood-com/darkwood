## Binary structure

The resource follows the classic Macintosh dialog-item format:

- A 16-bit item count minus one.
- For each item: a 4-byte placeholder, an 8-byte QuickDraw rectangle, a 1-byte item type, a 1-byte data length, and the item data.
- Odd-length data is followed by an alignment byte.

| Type byte | Meaning              | Items       |
| --------- | -------------------- | ----------- |
| `0x04`    | Enabled button       | 1, 3        |
| `0x06`    | Enabled radio button | 6–16        |
| `0x80`    | Disabled user item   | 2, 4, 5, 19 |
| `0x88`    | Disabled static text | 20–23       |
| `0xA0`    | Disabled picture     | 17, 18      |

The disabled flag does not necessarily mean an item is invisible. Static text, pictures and custom items may be present for display or application-controlled drawing rather than user interaction.

## What this reveals about Hellcats

This is a particularly useful resource for the strict Godot port because it exposes the original scenario selection menu and some of the player's pre-mission configuration options.

The eight scenarios are organized into two columns, with four entries per column. The bottom portion contains the `Fuel:` and `Bombs:` controls, followed by `Cancel` and `OK`.

One important inconsistency should be preserved for further investigation: the right bounds of several scenario radio buttons extend beyond the declared dialog width of 422 pixels (up to 444 pixels). That may reflect oversized control rectangles or original layout behavior; it should not be silently corrected in the source data.

For a faithful reconstruction, the remaining dependencies are `PICT` ID 128 and the original code responsible for drawing the four `userItem` regions and handling scenario, fuel and bomb selections.
