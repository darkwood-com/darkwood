# Native edition (in progress)

The same game rules as the Original edition, on Godot's own facilities instead of the emulated
Macintosh. It starts as adapters around `../original/` (roadmap phase 6) and replaces the
emulated state subsystem by subsystem (phase 7), each checked against Original by deterministic
traces (phase 4). Native never changes Original.

What `--edition=native` runs today (`Game.tscn`, inheriting `original/Game.tscn`):

| Slice | Native | Still Original |
|---|---|---|
| Keyboard | `input/controls.gd`: every game command is a Godot InputMap action (remappable), posting the Mac key the program reads | the program, the emulated Macintosh, screen, mouse |
| Dialogs | `dialogs/dialog_manager.gd` (the Original Dialog Manager plus a snapshot of the front dialog's buttons, check boxes, radio buttons, static and edit text) and `dialogs/dialog_overlay.gd` (those items as Godot controls over the screen, at its scale) | the dialog records, ModalDialog, hit testing and editing, which the game reads and decides by; clicks reach it as Original's mouse events; user items (lists, maps) stay drawn by the game; the focused edit field shows a blinking caret, a fully selected one is inverted |
| Menus | `menus/menu_manager.gd` (the Original Menu Manager plus a snapshot of the bar and the menu pulled down) and `menus/menu_overlay.gd` (titles, rows, marks, key equivalents as Godot labels over the Mac bar) | MenuSelect's tracking and choice, MenuKey, the menus in their MENU handles; the Apple menu's title is the Mac's drawing |
| Game state (phase 7) | `state/native_overlay.gd`: the overlay's random-number generator (overlay_rng_init / overlay_rng_next, the 55-long ring and cursor) as typed state, loaded once from the overlay image, never written back to Mac memory; the trigonometry tables sin_fixed14 / cos_fixed14 / acos_fixed14 / atan_fixed14 read and the altitude curve table_lerp_1b2c0 reads, as typed arrays copied once; `state/world_object_view.gd` / `state/controller_view.gd`: typed views over the world object and controller records (no copy), plus `state/scene_view.gd` over the camera and object-pass globals; on them the per-frame object pass (update_object_camera_metric, _sort_far_objects, collect_near_objects, collect_far_objects, build_visible_object_list, update_object_distance_band, copy_object_vertex_buffer) and the aircraft AI control helpers (adjust_ai_throttle_vs_speed, max_ai_throttle_maybe_invert_679, invert_ai_bias_67b_if_positive, enqueue_control_inputs_avg4), the AI pursuit helpers (ai_bootstrap_climb_phase, ai_script_try_fire_burst, build_relative_steer_sample), the flight-model leaves on `state/aircraft_type_view.gd` (damp_short_if_below_0x200, compute_template_force_from_626, scale_template_field_38), object release (retire_entity, deactivate_object, age_contact_records, dispatch_overlap_collisions), the ground scatter (update_ground_scatter_objects), the replay camera path (place_camera_behind_object, turn_camera_toward_point, update_bailout_view, begin_replay_view, update_tracking_camera) and the camera angle readers and writers (tick_view_attached_object, face_object_to_camera, shape_free_plume, update_direction_needle on the views; update_heading_tape, update_radar_scope, overlay_frame_step, process_flight_input_and_outcome and its view helpers generated verbatim with routed memory accesses in `state/routed_port.gd` by `tools/native/gen_routed_port.py`), three blocks held in Godot (`state/native_block.gd`, typed fields at the original's addresses, zeroed where the host zeroes the overlay's bss; rollback switches `camera_angle_storage_godot`, `camera_position_storage_godot`, `view_state_storage_godot`): the camera angles 0x1d800..0x1d811, the camera position 0x1d830..0x1d83b and the view state (view_flag_d856, view_mode) 0x1d856..0x1d859, with all their readers and writers Native (28 generated in `state/routed_port.gd`, update_aircraft_entity among them), the replay camera path with its own state block in Godot (`state/replay_camera_state.gd`: camera_step, camera_heading / pitch, target_hold_frames, camera_goal; never in the Mac memory, zeroed where the host zeroes the overlay's bss, rollback switch `replay_camera_storage_godot`), copy_player_pose_to_camera, spin_object_heading and face_camera_heading | the heap allocator (addresses, headers, free blocks) and the overlay's code image in the Mac memory; buffers shared with the emulated Toolbox (present_spans_to_window's CopyBits buffer); the host program (CODE segments) and the Mac runtime (Toolbox, QuickDraw, windows, sound scheduling);  every other piece of the game's state |
| Saves | `saves/resource_manager.gd`: the resources the game writes kept in `user://native/saves.cfg` (a Godot ConfigFile): the pilots of HEL1 128 as fields (name, status, rank, offences, awards, tallies), the settings and caches as exact bytes; the player's Original saves (`user://resources`) imported once, read only, never written | the resource lookups and handles in Mac memory; HEL1 127's settings not yet mapped field by field |
| Sound driver (1.0.3) | `sound/sound_driver.gd`: the game's two-channel mixer on typed state (node rings, rate, handlers) instead of A5 globals and records in emulated memory; `sound/native_id02.gd` routes CODE 2's eight sound entries to it and runs its tick as the sound hook; `sound/native_speaker.gd` plays its samples directly (no SoundBase) | the sample bytes (the game's 'snd ' handles) read in the Mac memory; the tick schedule (the Sound Manager's VBL service); 1.0.4 keeps its own driver |

NATIVE_FIELDS: the A5 world without the sound block, the world above low memory, the RNG).
Everything not listed is the Original edition's, so Native plays exactly as Original does.
